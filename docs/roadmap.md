# LiliumOS Roadmap

> `main` 发布基线仍以已发布版本为准。最后核对：2026-08-17。
> 具体实现契约见对应 `docs/` 规格；跨 Agent 交接只记录工作上下文，不替代 Git 和仓库文档。

## 当前优先级

### P0：文档与上游同步安全

- 上游同步严格执行 `.claude/CLAUDE.md` / `AGENTS.md` 的审批闸门：先只读调研和汇报，再由 Emma 选择，获批后才建验收分支。
- merge 后运行 `bash scripts/check-em-patches.sh`（当前 74 项）和 `pnpm vitest run`。
- EM App 数据备份必须持续覆盖 Finance、Health、Shopping、Map 及 Finance 周期规则。
- 剧情剧场默认保持独立故事线与独立记忆；只有用户显式开启时才镜像进角色正常记忆。

### P1：Health 外部数据链收尾

核心 Health App 已完成：本地 IndexedDB、训练/睡眠/饮食/经期/症状/体重、周期推算、饮食文本/图片识别、角色聊天健康摘要和完整备份。

仍待完成：

- Apple Health 快捷指令导入的真实解析与增量同步（当前按钮仍提示开发中）。
- Notion HealthLog / Daily Routine 同步。
- Health App 内“让角色说说这周”的周评论入口与缓存。
- 对按需读取健康详情的触发边界补测试。

### P1：Notion 高级管理 App

- 新建独立 `apps/NotionApp.tsx`，不重写 Settings 的基础配置。
- 整合多库权限、TAG 查询、日记模板和标签管理。
- 复用并扩展 `utils/notionExtraConfig.ts`，保持 `NotionExtraDatabase.name` 字段契约。

### P1：Smart Home 真实设备验收

LiliumOS「共栖舱」App、Home Assistant REST 适配、演示模式、完整备份和角色 MCP 接入已完成。

仍待完成：

- 在常驻 Mac mini 上部署 Home Assistant，并接入两只 Tapo Matter 灯泡。
- 通过 VeSync 集成接入 Levoit Core 200S-P，核对实际实体名、风速和模式字段。
- 用真实设备验收开关、亮度、色温、净化器档位、场景和角色控制。

### P2：位置感知聊天

- 复用 `utils/geo.ts` 获取位置，通过 Google Places 反查地名与周边 POI。
- 新建 `utils/locationService.ts`，在 `chatRequestPayload.ts` 做可控、低 token 注入。
- 必须有显式权限、失败降级和隐私开关；不把实时位置写入 Engram。

### P2：日记系统整理

- 新建独立 `apps/DiaryApp.tsx`，统一交换日记与 Notion 日记入口。
- 增加多选/主次心情标签、封缄和情绪统计时间线。

### P2：共读增强

- Phase 2：角色回头回应用户写在已读段落的批注。
- 选中文字高亮。
- PDF 支持。

## 已完成

### 2026-08-18

- 合入七夕「星月梦境童话」完整活动：一次性北京时间邀请、特别时光永久入口、七个场景、记忆鹊桥、重逢与约定。
- 七夕首次生成明确确认 4 次模型 API，并按所选角色解析独立聊天 API；重看不调用模型，不重复写入私聊。
- 七夕活动卡与返回消息进入聊天历史，完整共同经历可被后续对话自然召回；契约见 `docs/qixi-special-moment.md`。
- Active Message 2.0 新增按角色独立的心跳醒来：默认 1 小时，可选 30 分钟、1/2/4 小时；Cloudflare 用隐藏的一次性任务滚动续排，网页关闭后仍能醒来。
- 心跳醒来后可使用角色 API 与获准工具，自行决定发消息或静默；热聊时可按角色选择“顺着当前话题自然补一句”或在 API 前跳过本轮（缺省），并沿用连续主动发送上限与代次控制。
- 心跳可按角色启用「省钱唤醒」，直接复用已有情绪副 API；普通聊天和普通主动消息不受影响，配置不完整时回落原 API。
- 心跳下一次触发围绕所选频率做确定性自然波动（约 10%，±5–20 分钟），避免固定整点出现，同时保证 Worker 重试不会分叉。
- 心跳新增睡眠硬闸：按角色时区优先读取日程 / 情绪里的明确睡眠区间，并以后备生成日程识别睡眠、午睡和休眠；睡着时只续排下一跳，不调用模型、副 API 或工具。
- 自定义生图完成真实在线验收：浏览器直连与主 Worker 中转均可返回图片，静态站点不再受上游 CORS 限制。
- 聊天照片画风集中为统一预设，新增日系透明水彩、半写实幻想与韩系精绘等常用方向，并明确画风参考不复制姿势、固定配色或背景物件。
- `/images/generations` 与 `/images/edits` 接入本地 API 调用记录，显示角色、模型、状态、耗时、参考立绘和 Worker 中转信息，且不保存 Key 或参考图 Base64。

### 2026-08-15 至 2026-08-16

- 完成 LiliumOS 对外品牌、PWA 名称、图标和 README 字标更新；仓库与 GitHub Pages 在用户完成完整备份后迁移到 `Emma-Zhuym/LiliumOS` 与 `/LiliumOS/`。

- 角色获得按需财务工具，可主动出于好奇或关心查看近期交易、搜索账目、汇总支出和读取账户快照；今日情报围绕角色自身的经济生活生成，也允许与消费相关的社交八卦。
- 删除不再推进的本地 XHS bridge；保留由主代理 Worker 提供的现有网络能力。
- 主动消息 2.0 接入详细错误字段、请求体 gzip 上行、云端聊天通知对齐和点击时请求通知权限；推送订阅与页面消息采用同一交付语义。
- 即时聊天发送前由当前设备重新登记送达目标，避免 localhost / 桌面端覆盖订阅后手机只收到失败；Worker 模型调用结果回写本机 API 日志，成功记录 token / 实际后端，失败记录脱敏原因。当前仍是“发送设备优先”而非多设备同时广播。
- 主动消息 Worker 的一键部署、自更新与手动入口统一使用 LiliumOS 发布源；更新完成后必须读回 bundle version，版本不符时改为明确失败并引导一次性手动覆盖，不能再把旧上游包误报成更新成功。
- 聊天兼容 Vertex 原生工具调用响应，避免把 `functionCall` 外层 JSON 当普通气泡逐字段显示。
- Notion 日记读取对瞬时网络故障增加重试，并让前台与主动消息路径共用同一容错逻辑。
- 接入聊天外观与模式切换修复，收紧快捷栏 API 预设标题高度，同时保持预设面板固定高度。
- 定向修复均已有对应回归测试；2026-08-16 品牌改名工作另行完成后再更新发布提交。

## 待决策项

- 邮局待寄队列超过 5 封时：部分接受、整批拒但友好提示，或提高限额。
- 角色时区下，小小窝/查手机/见面等界面时钟究竟显示角色时间还是设备时间。
- 多角色共同日程采用“共享少量锚点”还是更强同步。
