# 贴贴事后记录 spec

> 阿萌 2026-10-28：「我不喜欢在见面里写剧情，每次贴贴都靠我发消息说'刚才好喜欢'这种话，感觉有点没意思了」。
> 定稿：日记样式（A）+ 顶上三格（什么时候 / 多久 / 在哪）；记忆写成「事实为主、补一两句感受」的一条卧室记忆；健康日历上打个小记号。
> 样稿 https://claude.ai/artifact/6qP9jsBL2qvyqbBnuHYwtT

## 一次贴贴的流程

1. 她点工具栏「贴贴」→ 照旧告诉 mini 心跳闭嘴 2 小时；**同时本机记下开始时刻**（`localStorage em_tietie_session_v1:<charId>` = `{ startedAt, until }`，已在里面就保留最早的开始）。
2. 她点「结束贴贴」→ mini 照旧 `intimacy_done`；本机取出开始时刻，发 `em-tietie-ended` 事件，聊天页接住，用**角色自己的 API** 写记录。
3. 忘了点结束、2 小时到了：下次打开这个角色的聊天，发现本机那条已经过了 `until`，补写（`endedBy: 'timeout'`，时长用 TA 自己估的）。
4. 写完：聊天里落一张卡（`role: system`，`metadata.kind = 'tietie_card'` + `tietieId`），紧跟着 TA 发一两条事后的话（普通 assistant 消息），她接着回就行。
5. 写不出来（API 拒写、超时、解析失败两次）：照样落卡，卡上「没写出来 · 再写一次」，点了重写，同一张卡原地更新。

## TA 写什么（一次调用，JSON）

- 材料：`ContextBuilder.buildCoreContext(char, user, false)` 的人设；开始前最近 30 条聊天（含见面）+ 两个人的时间里的所有消息（含见面，最多 80 条）；最近三次的记忆（防重复同样的流程和姿势）。
- 期间有原文就照实记、不编矛盾的细节；没有原文就由 TA 按前面的调情、人设和你们的习惯写这一次（这正是阿萌不用再写剧情的地方）。
- 输出：`title`（≤10 字）、`oneLine`（一句感受，卡片上）、`place`（≤6 字）、`minutes`、`story`（3–6 段第一人称日记，直白可露骨）、`memory`（100–150 字，先事实后感受）、`after`（1–2 条事后发给她的微信短句）。

## 存在哪

- 独立库 `LiliumOS_Tietie`（`utils/tietieDb.ts`），store `records`，主键 `id = <charId>_<startedAt>`（同一次不会写两份）。
- 卡片消息的 `content` 是给后续聊天上下文看的那一行：`（你们刚度过了两个人的时间 · 第N次《名字》：memory）`。日记全文不进聊天上下文。
- `memory` 写成一条**卧室记忆**（标签「贴贴」，重要度 7），有 embedding 当场向量化。角色没开记忆宫殿就不写。日记页末尾「TA 记住的」能删（连向量一起删）。
- 心跳不读记忆宫殿；amsg 只读门牌。全文不进心跳快照，快照里只有卡片那一行。
- 完整备份和文字备份都带 `emTietieRecords`；恢复按 id 覆盖。

## 在哪看

- 聊天卡（`components/tietie/TietieChatItem.tsx`）：名字、第几次、一句话、在哪 · 多久、「翻开」。
- 日记（`components/tietie/TietieDiary.tsx`）：玫瑰 tint 底上一张白纸，标题衬线、三格、正文衬线 400（同烛下信笺的例外）、手写体签名，末尾「TA 记住的」。
- 健康 App 日历：那一天一颗小心形；点开那天多一行「贴贴 · 角色 · 时刻 · 多久」。只是记号：不进健康摘要（角色看不到），不影响经期推算。

## 本次不做

- 没配对 mini 时的入口（贴贴按钮本来就只在配对后出现）
- 她在日记里改写 / 补一句
