# 厨房 3D 第一版

## 已实现的范围

库存页的「看看冰箱」按需加载 Three.js。当前模型为原创圆角双门冰箱，上层冷冻、下层冷藏、底部两个透明抽屉。直接点击门独立开合，两区库存同时在场景中；关闭门时不显示该层编号。点食材或名称选中后，可进入详情，冷藏食材可移到层板/门内上层/门内下层。详情清零仍复用原 `FINISH` 操作。不导入演示食物，不另存数量。

第一版一个模型代表一条批次，不按鸡蛋个数复制，也不按液体余量变形。牛奶/果汁暂用纸盒，鸡蛋与肉使用对应 Kenney 模型，其他食物用袋子。名称匹配只是外观提示；它不改变食材类型或库存。

## 文件边界

- `utils/kitchenDb.ts`：唯一库存事实来源。批次增加可选 `fridgePlacement`（shelf / door-upper / door-lower），旧数据缺省为层板；不升级数据库版本。`moveLot` 仅允许移动现有冷藏批次，改摆放不改数量、余量、日期或收纳分区，不产生数量账本事件。该字段随原批次备份往返，并在清零/撤销时保留；移回原位通过摆放按钮完成，原撤销按钮仍只撤销数量事件。
- `utils/kitchenSceneLayout.ts`：只读投影。仅 quantity > 0 且 storageZone 为 fridge/freezer 的批次进入场景，按创建时间与 id 排序；每组冷藏层板 9 条、冷冻 3 条、门上/下层各 2 条，超出翻组。门内位置使用相对门轴的局部坐标。最后一页消失时钳制到有效页；清零/撤销、位置编辑自然反映在下一次投影中。
- `components/kitchen/KitchenFridgeScene.tsx`：模型加载、定向相机、门动画、模型命中检测、文字替代入口。加载失败仍能从列表处理库存。
- `scripts/build-kitchen-model.mjs`：原创参数化建模，输出 `public/kitchen/models/fridge.glb`。不用依赖 Blender 安装；包含上下门轴、透明空心抽屉、玻璃搁板、内胆筋条、风口、灯罩、橡胶门封与金属把手。烤漆颗粒和拉丝法线 PNG 嵌入 GLB，可作为普通 glTF 导入 Blender；尚未在 Blender 重新验收。门轴为 `DoorPivot` / `FreezerDoorPivot`；抽屉为 `CrisperLeft` / `CrisperRight`。模型约 2.3 MB，81 个网格，未做最终移动端压缩。
- `public/kitchen/`：随站点发布的模型与版权说明。食材 GLB 仍引用同目录的 `Textures/colormap.png`，不能漏掉。

## 运行与性能边界

不新增依赖，复用项目现有 Three.js；场景懒加载，像素倍率上限 1.5，只在加载、尺寸变化与门/抽屉动画时绘制，离屏/后台停止绘制。使用 RoomEnvironment 生成环境反射，使玻璃和金属可辨。退出时释放画布、几何、材质、贴图、环境图、观察器和事件；迟到的加载结果也释放。减少动态效果时直接到最终位置。关门先收回抽屉。模型不参与库存备份，换模型不迁移数据。

模型配 44px 编号点击区与名称按钮，小屏幕长名称省略，选中面板看全名。门上模型挂在冷藏门轴下，编号由当前世界坐标投影，随门一起移动。上下门目标角度各自保存；只关闭冷藏门才收回抽屉。键盘/读屏有各门的等价按钮，普通画面不再展示分区标签。相机固定，不提供拖拽、缩放或物理碰撞。
