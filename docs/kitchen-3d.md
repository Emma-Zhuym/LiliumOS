# 厨房 3D 第一版

## 已实现的范围

库存页的「看看冰箱」按需加载 Three.js。单开门冰箱与三层隔板展示真实冷藏批次，模型或编号点击进入现有详情页；详情清零复用原 `FINISH` 操作，返回库存页可撤销。不导入演示食物，不另存数量。

第一版一个模型代表一条批次，不按鸡蛋个数复制，也不按液体余量变形。牛奶/果汁暂用纸盒，鸡蛋与肉使用对应 Kenney 模型，其他食物用袋子。名称匹配只是外观提示；它不改变食材类型或库存。

## 文件边界

- `utils/kitchenDb.ts`：唯一库存事实来源，本轮不改存储结构。
- `utils/kitchenSceneLayout.ts`：只读投影。仅 quantity > 0 且 storageZone = fridge 的批次进入场景，按创建时间与 id 排序，每页最多 9 条。最后一页消失时钳制到有效页；清零/撤销、位置编辑自然反映在下一次投影中。
- `components/kitchen/KitchenFridgeScene.tsx`：模型加载、定向相机、门动画、模型命中检测、文字替代入口。加载失败仍能从列表处理库存。
- `scripts/build-kitchen-model.mjs`：从仓库保留的 Kenney OBJ 重建 `public/kitchen/models/fridge.glb`。不用依赖 Blender 安装，门轴名 `DoorPivot`；底部 Y=0、正面 +Z、隔板表面 Y=0.3/0.76/1.22。
- `public/kitchen/`：随站点发布的模型与版权说明。食材 GLB 仍引用同目录的 `Textures/colormap.png`，不能漏掉。

## 运行与性能边界

不新增依赖，复用项目现有 Three.js；场景懒加载，像素倍率上限 1.5，只在加载、尺寸变化与门动画时绘制，离屏/后台停止绘制。退出时释放画布、几何、材质、贴图、观察器和事件；迟到的加载结果也释放。减少动态效果时门直接到最终角度。模型不参与库存备份，换模型不迁移数据。

每组 9 个模型配 44px 编号点击区与名称按钮，小屏幕长名称省略，进入详情看全名。相机固定，不提供拖拽、缩放或物理碰撞。

## 验证与下一步

49 项厨房定向测试通过：20 条库存分页、零库存/其他位置排除、少量余量、缺失贴图文件检查、门轴与隔板契约，以及场景入口 → 详情清零 → 返回后移除 → 撤销恢复。生产构建通过，全仓类型检查仍有既存问题，厨房文件无错误。EM 哨兵 82/83，既存聊天搜索入口缺失。

390×844 本地浏览器确认带贴图的冰箱与食材、按钮开门、点击鸡蛋模型进入真实详情；没有修改用户库存。正式 iPhone/PWA、断网/上下文丢失及长时间性能未实机验收。清零与撤销链路在隔离自动测试验证，未在用户库存中试扣。
