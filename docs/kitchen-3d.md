## 2026-10-14 · 纸签飞进冰箱（小帕，开发分支，待 Emma 手机上看手感）

- **什么时候飞**：手动放进、拍小票放进之后，场景记着上次有哪些批次，新出现的（一分钟内建的、不是待收纳）每样一张纸签，一张接一张隔 170ms，最多六张。第一次打开厨房、减少动态效果时不飞。
- **纸签**（`makeFlyTag`）：小牛皮纸吊牌，右边两个角切掉、左边打孔拴一截线、手写名字，左边按去处染一条色（冷藏 / 冷冻 / 常温柜）。自己管自己的贴图，飞完就释放，不进 `setContents` 那一批。
- **怎么飞**（760ms，起飞前等 420ms 让面板先收下去）：从画面下方偏右飘起来，沿二次曲线飞，面朝镜头、左右翻几下越到后面越稳、越飞越小。
  - 门关着 → 飞到那扇门把手那侧的门缝；飞到四成时门开一条缝（0.26 弧度，里面的灯亮一点），纸签钻进去淡掉，最后一张进去 140ms 后门「嗒」地合上（门本来的弹簧，带一点回弹）。后面还有往同一扇门飞的就先不关。
  - 门开着 → 直接落到那一样在层板上的位置，那一样落地之前先藏起来，纸签到了才出现。
  - 常温柜 → 落到冷藏门上「柜子里」那张纸上，纸晃一下。
- 验证：预览面板在后台、帧率被压，临时把飞行时间调到 8 秒截了中途：纸签从下方飘起、飞到冷藏门门缝时门开了一条缝、钻进去淡掉，之后门关好、小票多了一行；常温柜的薯片落到「柜子里」那张纸上、清单多了一行；控制台没有报错。时间已改回 760ms。

## 2026-10-14 · 橡皮擦掉（小帕，开发分支，待 Emma 手机上看手感）

## 2026-10-14 · 手写动效：打勾、划线、批注（小帕，开发分支，待 Emma 手机上看手感）

  - 要买清单打勾：方框里短的一笔 → 长的一笔（会稍微冲出方框，像手写）→ 一道墨线划过名字 → 字淡下去，共 640ms。

## 2026-10-13 · 小票按「吃到哪了」分两块，耐放的放「慢慢吃」（小帕，开发分支，待 Emma 验收）

- **为什么**：Emma 看采购小票划掉多少来决定什么时候再去买菜；番茄酱这种要吃几个月的放在冰箱里没问题，但不能让旧小票一直挂着「这次买的没吃完」。
- **耐放**（`isLongKeeping`）：买回来时保质期 ≥ 30 天就算（拍小票时 AI 会估好）；没填保质期的按名字认（酱、调料、油、醋、米面、罐头、咖啡豆……），放常温柜的也算。跟放在哪无关，番茄酱照样画在冷藏室。分错了改保质期就行，不加开关。
- **小票上**：买回来的分两段——要吃掉的在上，虚线下「慢慢吃」字小一号、淡一点；耐放的吃完照样划掉写「3 个月吃完」。门上那张也一样，纸长改成跟着内容走（原来底下空一大截），不再印「共 N 样」。
- **记录页**：要吃掉的都划掉了的小票（`finished`）折成一截撕下来的短票根放到下面「吃完了的小票」（两边虚线夹着的小标题）：日期 + 一小段条形码，那次买的东西划掉了排一行，慢慢吃的淡淡跟在后面，底边锯齿，一沓左右错一点像随手叠的；点开看整张，展开时票根只留日期和「收起」；还没吃完的整张展开在上，新的在前。只买了酱料的、开张那张直接算吃完。

验证：厨房测试 79 项通过。本地预览两次采购：上周的牛奶、鸡蛋吃完、西兰花丢了、番茄酱还在 → 折到「吃完了」，点开番茄酱在慢慢吃那段；这周的酸奶、菠菜没吃完、牛肉末当天吃完 → 展开在上，橄榄油、咖啡豆在慢慢吃；门上小票同样分段。测完删掉预览数据。

## 2026-10-13 · 要买清单（小帕，开发分支，待 Emma 手机验收）

- **数据**：厨房库加一张 `shopping` 表（库版本 1 → 2，旧数据不动），随完整备份走（`emKitchenShopping`，`OSContext` 的 kitchen 备份块里多一行）。同名没划掉的不重复加，划掉的同名再加就重新打开。增删改不进操作记录、不弹撤销。
- **冷冻门右半边**：一条窄热敏纸「要买的」，每行一个小方框；点哪行就划掉 / 取消（手写的勾 + 一道线），划掉的排到后面、留两天再从门上消失；点标题、空白或「还有 N 样」打开整张清单。一样都没有也贴着，写「点这里写」。深灰磁贴压右上角。
- **整张清单**（`KitchenShoppingList`）：能写、能删、能清掉划掉的；上面一排建议——便利贴上「快用完了 / 只剩一个」的，和两周内用完了又没再买的（自己做的菜不建议）。每样食物那页也多了「加进要买清单」。
- **买回来自动划掉**：手动放进或拍小票放进后，名字对得上的划掉（`shoppingMatches`：「牛奶」对「有机全脂牛奶」；单字只认「小葱、生姜、大米」这种常见前缀，「玉米」不算「米」），提示条上写划掉了几样。每行记下是哪一笔放进划掉的（`boughtBy`），撤销那一笔时勾跟着取消（在 `undoLatest` 同一个事务里），手动划的不动。
- **小票上划掉吃完的**（2026-10-13 Emma 要）：采购小票上买回来的那一样，现在数量归零了就划掉——门上那张字淡下去、手写一道线、右边写「3 天吃完」或「2 周丢了」（最后一笔是丢掉）；操作记录里名字划线、数量换成同样的字。用了多久：两周内按天、两个月内按周、再久按月——Emma 要的是看自己吃得多快，所以**不做数字统计**（小票底下原来的「买 5 样 · 吃掉 2」去掉了，2026-10-13）。番茄酱这种吃几个月的：那张旧小票上它一直是「+1 件」，哪天吃完了再划掉、写「3 个月吃完」，小票本身不用管它。只吃了一部分的不划。门上小票抬头改成「小厨房 · 采购」。

验证：厨房测试 76 项通过。本地预览：门上那张显示三样没划的 + 划掉的洗洁精，点「小葱」划掉；点标题打开整张清单，建议里有用完的「吐司」，点一下加上；再手动放进「有机酸奶」，清单上的「酸奶」自动划掉、提示「要买清单划掉了 1 样」；测完删掉预览数据。

验证：厨房测试 72 项通过。本地预览放了 9 样假东西（含番茄炖牛腩今天到期、咖喱饭、速冻饺子、冷冻披萨、冷冻牛肉），冷冻门上四行都对、冷冻牛肉没上，点「速冻饺子」那行打开的就是它；测完删掉预览数据。

## 2026-10-13 · 拍小票入库（小帕接 GPT 的识图底层，开发分支，待 Emma 拿真小票验收）

- **入口**：顶栏加号 → 最上面「拍小票」（相册或相机都行）。读小票用的 API 在旁边「换一个」里挑，选项就是「设置 → API」的预设（按分组排），只存预设 id 在本机 localStorage（`utils/kitchenReceiptApi.ts`），不进备份；跟设置里的独立识图互不相干。预设得是能看图的模型。
- **识图**（`utils/kitchenReceiptVision.ts`，GPT 起的头）：照片长边缩到 2000 像素、JPEG 压一下再发；一张图只调一次。用宽松的 `json_object` 模式——严格 `json_schema` 在很多中转站和 Claude / Gemini 兼容接口上直接 400。提示词要求 `name` 写**中文常用名**（去品牌和营销词），小票原文 `rawLabel` 一字不改留着；顺带让它建议放冷藏 / 冷冻 / 常温柜、估能放几天、标出不是吃的（纸巾默认不勾）。
- **单位按小票来**（Emma 2026-10-13 定）：数的是「件」，称重的照写磅 / 盎司、不换算；1 gal、18 ct 这类是包装规格。没写数量的行就是 1 件，只有称重没看清重量才要确认。手动添加的单位也换成 件 / 磅 / 盎司 / 克 / 毫升；个、包、袋、盒、大瓶小瓶不再给新东西选，旧数据照旧显示、编辑时保留原单位。
- **核对单**（`components/kitchen/KitchenReceiptScan.tsx`）：每行有勾选、中文名、数量和单位、放哪、能放到哪天；AI 不确定或缩写有几种解释的行标出原因，候选名点一下就换。确认后每样单独一笔（撤销一次撤一样），`operationId` 带 `receipt_` 前缀——小票分组靠它认出「这是买的」，所以速冻饺子不会被当成自己做的菜。
- **已知**：小票上那张采购记的是放进来的时间，不是小票上的购买日期（购买日期写在每样东西的 purchasedAt 里）。

验证：厨房测试 71 项通过。本地预览用假预设 + 拦下请求塞了一张六样东西的假识别结果，确认核对单、标黄的不确定行、候选名、纸巾默认不勾，放进去后单位 / 位置 / 规格 / 保质期都对，操作记录里成了一张「采购」小票；测完删掉假预设和预览数据。**还没拿真小票和真模型试过。**

- **无障碍**：门和抽屉各有按钮；开着的那格里每样东西、便利贴每一行都有读屏按钮；点不准时取 36px 以内最近的那一样。
- **和以前不同**：首页默认关着门（门才是主体）；不再有画面上的数字编号。

## 已实现的范围

库存页的「看看冰箱」按需加载 Three.js。当前模型为原创珍珠白圆角双门冰箱，上层冷冻、下层冷藏、底部两个透明抽屉。直接点击门独立开合，两区库存同时在场景中；关闭门时不显示该层编号。点食材或名称选中后，可进入详情，冷藏食材可移到层板/门内上层/门内中层/门内下层，冷冻食材可移到冷冻层板/门内上层/门内下层。详情清零仍复用原 `FINISH` 操作。不导入演示食物，不另存数量。

一个模型代表一条批次，不按液体余量变形。鸡蛋使用原创两排六格蛋盒，按个记录时显示最多 12 个剩余鸡蛋；超过 12 个只作一盒示意，完整数量看详情，按盒记录则显示满盒。牛奶/果汁暂用纸盒，肉使用对应 Kenney 模型，其他食物用袋子。名称匹配只是外观提示；它不改变食材类型或库存。

## 文件边界

- `utils/kitchenDb.ts`：唯一库存事实来源。批次增加可选 `fridgePlacement`（shelf / door-upper / door-middle / door-lower），旧数据缺省为层板；不升级数据库版本。`moveLot` 仅允许移动现有冷藏或冷冻批次，冷冻门拒绝中层；改摆放不改数量、余量、日期或收纳分区，不产生数量账本事件。该字段随原批次备份往返，并在清零/撤销时保留；编辑收纳分区时重置到层板。移回原位通过摆放按钮完成，原撤销按钮仍只撤销数量事件。
- `utils/kitchenFridgeSpec.ts`：模型脚本和投影共用的尺寸表、门轴名称与摆放选项。冷藏门三层、冷冻门两层；冷冻室内部上下两层，各层限制食品模型高度。
- `utils/kitchenSceneLayout.ts`：只读投影，所有 quantity > 0 的冷藏/冷冻批次同时进入一个场景，不分页。层板按模型占用宽度均衡分配到现有层板，门架保留指定上/中/下层；每层等比缩小到可用宽度，不改变数量或保存的位置。鸡蛋盒占宽 0.88，普通模型占宽 0.32（含间隔），避免互相穿插。数量很多时模型会变小，仍可通过完整名称列表选择。
- `components/kitchen/KitchenFridgeScene.tsx`：模型加载、正面对齐相机、门动画、模型命中检测、文字替代入口。加载失败仍能从列表处理库存。
- `utils/kitchenBackdrop.ts`：装饰房间（浅蓝墙、浅木地板与白色踢脚线），木纹/错缝用一张 512px 本地生成贴图重复铺设，不依赖外部素材。墙与地板接收现有主光投影，不新增阴影图；背景网格不参与点击，退出时随场景统一释放几何、材质与贴图。最初的右侧并排构想已在手机比例体验后改为 pantry 独立一页；当前未添加柜子或柜内库存界面。
- `scripts/build-kitchen-model.mjs`：原创参数化建模，输出 `public/kitchen/models/fridge.glb`。不用依赖 Blender 安装；包含上下门轴、透明空心抽屉、玻璃搁板、内胆筋条、风口、灯罩、双层橡胶门封与银色把手。烤漆颗粒和拉丝法线 PNG 嵌入 GLB，可作为普通 glTF 导入 Blender；尚未在 Blender 重新验收。门轴为 `DoorPivot` / `FreezerDoorPivot`；抽屉为 `CrisperLeft` / `CrisperRight`。冰箱模型约 1.9 MB，54 个复用网格资源，未做最终移动端压缩。抽屉使用独立的淡灰蓝透明材质，侧壁比正面略深，底边、竖向接缝和顶沿亮线帮助白色内胆上的空盒轮廓辨识；未增加折射渲染或阴影贴图。
- `public/kitchen/`：随站点发布的模型与版权说明。食材 GLB 仍引用同目录的 `Textures/colormap.png`，不能漏掉。

## 运行与性能边界

不新增依赖，复用项目现有 Three.js；场景懒加载，像素倍率上限 1.5，只在加载、尺寸变化与门/抽屉动画时绘制，离屏/后台停止绘制。使用 RoomEnvironment 生成环境反射，使玻璃和金属可辨。退出时释放画布、几何、材质、贴图、环境图、观察器和事件；迟到的加载结果也释放。减少动态效果时直接到最终位置。关门先收回抽屉。模型不参与库存备份，换模型不迁移数据。

模型配 44px 编号点击区与名称按钮；`utils/kitchenSceneMarkers.ts` 将挤在一起的可见编号移到最近可用空位，优先保留原投影点且限制在画布内。画布极端拥挤、无空位时仍保留全部编号，下方名称列表可继续选择。小屏幕长名称省略，选中面板看全名。门上模型挂在对应冷藏/冷冻门轴下，编号由当前世界坐标投影，随门一起移动。上下门目标角度各自保存；只关闭冷藏门才收回抽屉。键盘/读屏有各门的等价按钮，普通画面不再展示分区标签。相机固定朝正前方，左右没有斜视角，微俯视只露出脚边地面；两门展开 112°。画布宽高比为 1:1.18、最高 420px，手机随宽度收紧，避免大片空地。不提供拖拽、缩放或物理碰撞。使用定向主光、弱侧后补光和随各门打开渐亮的中性内灯；只有主光使用一个 1024px VSM 阴影贴图。层板下方、内壁转角与抽屉底部复用柔边接触阴影贴图表现凹处暗部，它们是固定装饰遮罩，不是真实光线遮挡计算。抽屉底部遮罩随抽屉移动，不参与点击；这些场景内光影不改变 UI 背景。退出释放贴图、阴影渲染目标。
